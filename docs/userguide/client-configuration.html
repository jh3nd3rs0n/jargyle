Overview

This document discusses how to further use the client API by means of configuration.

(TCP) Socket Connection Types

There are two types of connections a TCP socket (Socket) can make: an extemporaneous connection and a prepared connection. Each connection type has its advantages and disadvantages.

Extemporaneous (TCP) Socket Connection Type

An extemporaneous connection occurs when creating a Socket from one of the following methods:

  • SocketFactory.newSocket(java.lang.String host, int port)
  • SocketFactory.newSocket(java.lang.String host, int port, java.net.InetAddress localAddr, int localPort)
  • SocketFactory.newSocket(java.net.InetAddress address, int port)
  • SocketFactory.newSocket(java.net.InetAddress address, int port, java.net.InetAddress localAddr, int localPort)

When an extemporaneous connection is about to be made, no preparation is made for the Socket before connecting.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        SocketFactory socketFactory = SocketFactory.getInstance();
        Socket socket = socketFactory.newSocket("example.com", 443);
        // ...
    }
}

Here are the following advantages/disadvantages:

Advantages:

  • When having the Socket's traffic set through a SOCKS server, if a target host name is provided for the Socket to connect to (java.lang.String host), the target host name will be resolved by the SOCKS server

Disadvantages:

  • Some Socket configuration might not be applied after the connection is made. Only a prepared connection can have such Socket configuration applied earlier.
  • No timeout in milliseconds can be specified for how long a wait for the Socket to connect.

Prepared (TCP) Socket Connection Type

For a prepared connection, the following occurs:

  1. An unbound and unconnected Socket is created from the method SocketFactory.newSocket().
  2. The Socket is bound by using the method Socket.bind(java.net.SocketAddress bindpoint).
  3. Additional configuration is applied to the Socket (optional).
  4. The Socket is connected by using either of the following methods:
  • Socket.connect(java.net.SocketAddress endpoint)
  • Socket.connect(java.net.SocketAddress endpoint, int timeout)

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.InetSocketAddress;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        SocketFactory socketFactory = SocketFactory.getInstance();
        Socket socket = socketFactory.newSocket();
        socket.bind(new InetSocketAddress(null, 0));
        socket.connect(new InetSocketAddress("example.com", 443));
        // ...
    }
}

Here are the following advantages/disadvantages:

Advantages:

  • Socket configuration that can only be applied before a connection is made can be applied.
  • A timeout in milliseconds can be specified for how long a wait for the Socket to connect (int timeout).

Disadvantages:

  • When having the Socket's traffic set through a SOCKS server, if a target host name is provided for the TCP socket to connect to, the target host name is resolved through the local system not the SOCKS server.

Configuring the SOCKS Server TCP Socket

Objects that have their traffic routed through the SOCKS server each has a client. Each client has an underlying TCP socket to the SOCKS server. In this documentation, this underlying TCP socket is called the SOCKS server TCP socket.

Depending on the object, the SOCKS server TCP socket can be configured in only one of the following ways:

  • Configuring the object. Configuring certain objects configure their SOCKS server TCP sockets without any special properties required. Socket would be such an object.
  • Configuring the object and using properties prefixed with socksClient.socksServerSocket. Configuring certain objects configure some parts of their SOCKS server TCP sockets but the special properties are required to configure other parts of their SOCKS server TCP sockets. ServerSocket would be such an object.
  • Using properties prefixed with socksClient.socksServerSocket. Configuring certain objects does nothing to their SOCKS server TCP sockets. DatagramSocket would be such an object. Special properties are required to configure their SOCKS server TCP sockets.

Binding the SOCKS Server TCP Socket to a Host Name or Address

You can bind the SOCKS server TCP socket to a host name or to a host address.

For a Socket, you can provide the host name or address as a java.lang.String or a java.net.InetAddress to the following methods:

  • SocketFactory.newSocket(java.lang.String host, int port, java.net.InetAddress localAddr, int localPort): The third method argument localAddr is used to bind the SOCKS server TCP socket to a host name or address.
  • SocketFactory.newSocket(java.net.InetAddress address, int port, java.net.InetAddress localAddr, int localPort): The third method argument localAddr is used to bind the SOCKS server TCP socket to a host address.
  • Socket.bind(java.net.SocketAddress bindpoint): The host name or address of the provided java.net.SocketAddress is used to bind the SOCKS server TCP socket to a host name or address.

For all other objects, you would use the property socksClient.socksServerSocket.bindHost.

The host address can be an IPv4 address or an IPv6 address.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.InetSocketAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        /*
         * Examples of binding the SOCKS server TCP socket to a host name or 
         * address:
         * 
         * System.setProperty("socksClient.socksServerSocket.bindHost", "a96p08.local");
         * 
         * System.setProperty("socksClient.socksServerSocket.bindHost", "192.168.1.231");
         * 
         * System.setProperty("socksClient.socksServerSocket.bindHost", "fe80::34ef:938a:402f:e526%17");
         * 
         */
        SocketFactory socketFactory = SocketFactory.getInstance();
        /*
         * Examples of binding the SOCKS server TCP socket to a host name or
         * address through a Socket:
         * 
         * Socket socket = socketFactory.newSocket("example.com", 443, "a96p08.local", 0);
         * 
         * Socket socket = socketFactory.newSocket("example.com", 443, "192.168.1.231", 0);
         * 
         * Socket socket = socketFactory.newSocket("example.com", 443, "fe80::34ef:938a:402f:e526%17", 0);
         * 
         * InetAddress address = InetAddress.getByName("example.com");
         * InetAddress localAddr = InetAddress.getByName("a96p08.local");
         * Socket socket = socketFactory.newSocket(address, 443, localAddr, 0);
         * 
         * Socket socket = socketFactory.newSocket();
         * socket.bind(new InetSocketAddress("a96p08.local", 0));
         * 
         */
        // ...
    }
}

Binding the SOCKS Server TCP Socket to a Host Address from a Network Interface

Instead of binding the SOCKS server TCP socket to a specified host address, you can bind it to a host address from a specified network interface.

For a Socket, you can provide the name of the network interface to NetInterface.newInstanceFrom(java.lang.String s) and receive a NetInterface object that can provide you a host address.

For all other objects, you would use the property socksClient.socksServerSocket.netInterface.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import com.github.jh3nd3rs0n.jargyle.common.net.NetInterface;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.InetSocketAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        /*
         * Example of binding the SOCKS server TCP socket to a host address 
         * from a network interface:
         * 
         * System.setProperty("socksClient.socksServerSocket.netInterface", "eth0");
         * 
         */
        SocketFactory socketFactory = SocketFactory.getInstance();
        /*
         * Examples of binding the SOCKS server TCP socket to a host address 
         * from a network interface through a Socket:
         * 
         * InetAddress address = InetAddress.getByName("example.com");
         * InetAddress localAddr = NetInterface.newInstanceFrom("eth0")
         *     .getHostAddresses().get(0).toInetAddress();
         * Socket socket = socketFactory.newSocket(address, 443, localAddr, 0);
         * 
         * Socket socket = socketFactory.newSocket();
         * socket.bind(new InetSocketAddress(
         *     NetInterface.newInstanceFrom("eth0")
         *         .getHostAddresses().get(0).toInetAddress(), 
         *     0));
         * 
         */
        // ...
    }
}

You can also specify which host address types to choose from the network interface.

For a Socket, you can provide the host address types to NetInterface.getHostAddresses(HostAddressTypes hostAddressTypes) to the NetInterface object.

For all other objects, you would use the property socksClient.socksServerSocket.bindHostAddressTypes.

import java.net.InetSocketAddress;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");

         * Example of binding the SOCKS server TCP socket to a host address 
         * from a network interface:
         * 
         * System.setProperty("socksClient.socksServerSocket.netInterface", "eth0");
         * System.setProperty("socksClient.socksServerSocket.bindHostAddressTypes", "HOST_IPV4_ADDRESS");
         *

Applying Socket Settings to the SOCKS Server TCP Socket

You can apply socket settings to the SOCKS server TCP socket.

For a Socket, you would use the following methods:

  • Socket.setKeepAlive(boolean on)
  • Socket.setOption(java.net.SocketOption<T> name, T value)
  • Socket.setReceiveBufferSize(int size)
  • Socket.setReuseAddress(boolean on)
  • Socket.setSendBufferSize(int size)
  • Socket.setSoLinger(boolean on, int linger)
  • Socket.setSoTimeout(int timeout)
  • Socket.setTcpNoDelay(boolean on)
  • Socket.setTrafficClass(int tc)

For a ServerSocket, you would use the following methods:

  • ServerSocket.setOption(java.net.SocketOption<T> name, T value)
  • ServerSocket.setReceiveBufferSize(int size)
  • ServerSocket.setReuseAddress(boolean on)
  • ServerSocket.setSoTimeout(int timeout)

For all other objects, you would use the property socksClient.socksServerSocket.socketSettings.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.InetSocketAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        /*
         * Example of applying socket settings to the SOCKS server TCP socket:
         * 
         * System.setProperty("socksClient.socksServerSocket.socketSettings", "SO_RCVBUF=256,SO_SNDBUF=256");
         * 
         */
        /*
         * Example of applying socket settings to the SOCKS server TCP socket 
         * through a Socket:
         * 
         * SocketFactory socketFactory = SocketFactory.getInstance();
         * Socket socket = socketFactory.newSocket();
         * socket.setReceiveBufferSize(256);
         * socket.setSendBufferSize(256);
         * 
         */
        /*
         * Example of applying socket settings to the SOCKS server TCP socket
         * through a ServerSocket:
         *
         * ServerSocketFactory serverSocketFactory = ServerSocketFactory.getInstance();
         * ServerSocket serverSocket = serverSocketFactory.newServerSocket();
         * serverSocket.setReceiveBufferSize(256);
         * serverSocket.bind(new InetSocketAddress(null, 5000));
         * Socket socket = serverSocket.accept();
         * socket.setSendBufferSize(256);
         *
         */
        // ...
    }
}

Enabling SSL/TLS-layered TCP Traffic Between the Client and the SOCKS Server

You can enable SSL/TLS-layered TCP traffic between the client and the SOCKS server under the following condition:

  • The SOCKS server accepts SSL/TLS connections.

By default, SSL/TLS-layered TCP traffic between the client and the SOCKS server is disabled. To enable SSL/TLS-layered TCP traffic between the client and the SOCKS server, you will need to have the property socksClient.ssl.enabled set to true. In addition, you will need to have the property socksClient.ssl.trustStoreFile to specify the SOCKS server's key store file used as a trust store (this file would need to be created by Java's keytool utility). Also, you will need to have the property socksClient.ssl.trustStorePassword to specify the password for the SOCKS server's trust store file.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        System.setProperty("socksClient.ssl.enabled", "true");
        System.setProperty("socksClient.ssl.trustStoreFile", "jargyle.jks");
        System.setProperty("socksClient.ssl.trustStorePassword", "password");
        // ...
    }
}

If the SOCKS server wants the client to authenticate using SSL/TLS, you will need to have the property socksClient.ssl.keyStoreFile to specify the client's key store file (this file would need to be created by Java's keytool utility). Also, you will need to have the property socksClient.ssl.keyStorePassword to specify the password for the client's key store file.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        System.setProperty("socksClient.ssl.enabled", "true");
        System.setProperty("socksClient.ssl.keyStoreFile", "client.jks");
        System.setProperty("socksClient.ssl.keyStorePassword", "drowssap");
        System.setProperty("socksClient.ssl.trustStoreFile", "jargyle.jks");
        System.setProperty("socksClient.ssl.trustStorePassword", "password");
        // ...
    }
}

Accessing the SOCKS Server Using SOCKS5 Authentication

The client has the following SOCKS5 authentication methods to choose from when accessing the SOCKS5 server:

  • NO_AUTHENTICATION_REQUIRED: No authentication required
  • GSSAPI: GSS-API authentication
  • USERNAME_PASSWORD: Username password authentication

Accessing the SOCKS Server Using GSS-API Authentication

To access the SOCKS server using GSS-API authentication, you will need to have the property socksClient.socks5.methods to have GSSAPI included. You will also need to specify Java system properties to use a security mechanism that implements the GSS-API (for example, Kerberos is a security mechanism that implements the GSS-API) and you will also need to specify the GSS-API service name for the SOCKS5 server.

The following is a sufficient example of using the Kerberos security mechanism:

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "javax.security.auth.useSubjectCredsOnly", "false");
        System.setProperty(
            "java.security.auth.login.config", "login.conf");
        System.setProperty("java.security.krb5.conf", "krb5.conf");
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        System.setProperty("socksClient.socks5.methods", "GSSAPI");
        System.setProperty(
            "socksClient.socks5.gssapiauthmethod.serviceName",
            "rcmd/jargyle.net");
        // ...
    }
}

The Java system property javax.security.auth.useSubjectCredsOnly with the value false disables JAAS-based authentication to obtain the credentials directly and lets the underlying security mechanism obtain them instead.

The Java system property java.security.auth.login.config with the value login.conf provides a JAAS configuration file for the underlying security mechanism.

login.conf:

com.sun.security.jgss.initiate {
  com.sun.security.auth.module.Krb5LoginModule required
  principal="alice"
  useKeyTab=true
  keyTab="alice.keytab"
  storeKey=true;
};

In login.conf, alice is a principal that is created by a Kerberos administrator.

Also in login.conf, alice.keytab is a keytab file also created by a Kerberos administrator that contains the aforementioned principal and its respective encrypted key.

The Java system property java.security.krb5.conf with the value krb5.conf provides the Kerberos configuration file that points to the Kerberos Key Distribution Center (KDC) for authentication.

krb5.conf:

[libdefaults]
    kdc_realm = JARGYLE.NET
    default_realm = JARGYLE.NET
    udp_preference_limit = 4096
    kdc_tcp_port = 12345
    kdc_udp_port = 12345

[realms]
    JARGYLE.NET = {
        kdc = jargyle.net:12345
    }

In krb5.conf, a KDC is defined as running at jargyle.net on port 12345 with its realm as JARGYLE.NET.

The property socksClient.socks5.gssapiauthmethod.serviceName with the value rcmd/jargyle.net is the GSS-API service name (or the Kerberos service principal) for the SOCKS server residing at jargyle.net.

Resolving Host Names From the SOCKS Server

By default, host name resolution from the SOCKS server occurs only when a Socket is created from the following methods:

  • SocketFactory.newSocket(java.lang.String host, int port): The first method argument host gets resolved from the SOCKS server
  • SocketFactory.newSocket(java.lang.String host, int port, java.net.InetAddress localAddr, int localPort): The first method argument host gets resolved from the SOCKS server

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        System.setProperty(
            "socksClient.socksServerUri", "socks5://jargyle.net:1234");
        SocketFactory socketFactory = SocketFactory.getInstance();
        Socket socket = socketFactory.newSocket("example.com", 443);
        // ...
    }
}

The client API comes with a HostResolver object to resolve host names. By default, the HostResolver object resolves host names through the local system. To enable the HostResolver object to have the host names resolved from the SOCKS server instead, you would need to set the property socksClient.socks.socksHostResolver.resolveFromSocksServer set to true. This property can only be used if the SOCKS server supports handling the RESOLVE request.

API example:

        SocketFactory socketFactory = SocketFactory.getInstance();        
        Socket socket = socketFactory.newSocket(inetAddress, 443);
        // ...
    }
}

Routing Traffic Through a Specified Chain of SOCKS Servers

You can have objects route traffic through a specified chain of SOCKS servers. To do this, you will need to create a chain of SocksClient objects with each SocksClient object specifying a SOCKS server.

API example:

package com.example;

import com.github.jh3nd3rs0n.jargyle.client.DatagramSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.HostResolver;
import com.github.jh3nd3rs0n.jargyle.client.HostResolverFactory;
import com.github.jh3nd3rs0n.jargyle.client.Properties;
import com.github.jh3nd3rs0n.jargyle.client.ServerSocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocketFactory;
import com.github.jh3nd3rs0n.jargyle.client.SocksClient;
import com.github.jh3nd3rs0n.jargyle.client.SocksServerUri;
import com.github.jh3nd3rs0n.jargyle.client.SocksServerUriScheme;

import java.io.IOException;

import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.ServerSocket;
import java.net.Socket;

public class ClientApp {
    public static void main(String[] args) throws IOException {
        SocksClient socksClient1 = SocksServerUriScheme.SOCKS5
            .newSocksServerUri("alpha-alpha.net", 11111)
            .newSocksClient(Properties.of());
        SocksClient socksClient2 = SocksServerUriScheme.SOCKS5
            .newSocksServerUri("beta-alpha.net", 22221)
            .newSocksClient(Properties.of(), socksClient1);
        SocksClient socksClient3 = SocksServerUriScheme.SOCKS5
            .newSocksServerUri("gamma-alpha.net", 33331)
            .newSocksClient(Properties.of(), socksClient2);
        SocketFactory socketFactory = 
            socksClient3.getSocksSocketFactory();
        // ...
    }
}

Objects that have traffic routed through a specified chain of SOCKS servers each has a SocksClient object. Each SocksClient object has an underlying TCP socket to the last SOCKS server in the chain. Within each underlying TCP socket to the last SOCKS server in the chain is another SocksClient object. Within each SocksClient object is an underlying TCP socket to the second-to-last SOCKS server in the chain and so on. All of these underlying TCP sockets are called the SOCKS server TCP sockets.

For configuring any of the SOCKS server TCP sockets, it is recommended to configure only the last SOCKS server TCP socket in the chain by setting the Properties object for the last SocksClient object.
